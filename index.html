Research brief · active work on LUMI

Four post-training tracks, each with a decision gate

These are Birger Moëll's current experiments using OpenEuroLLM checkpoints, datasets and tooling. The statuses are a 5 October 2026 LUMI snapshot; experimental checkpoints and queued jobs are separate from formal project releases.

01 / Reasoning SFTPublished v1 · new run in recovery

Reasoning with retention

The 2,000-step experimental checkpoint improved some reasoning tests but regressed GSM8K, IFEval and a code-related knowledge task. A new 524M-token continuation mixes translated reasoning with instruction replay; its latest launch stopped at chat-template validation before training.

Next gate Validate the loss mask, then compare reasoning, ordinary instructions, language behavior and repetition loops against the pinned parent.

02 / DPOTraining · evaluation pending

Preferences across three sources

A four-node 9B DPO run is training on about 1.48M staged pairs from translated Dolci, HelpSteer3 and UltraFeedback. Dolci dominates the natural-size mix. A step-9,000 snapshot exists, but training preference accuracy is not a held-out result.

Next gate Compare the checkpoint with its unchanged SFT parent on held-out preference pairs and general behavior by language.

03 / RLVR64 updates evaluated · longer run queued

Does verifiable math reward transfer?

The public Phase A checkpoint anchors a completed 64-update qualification. Its final export reached 45.12% on a 512-prompt multilingual procedural holdout, but 4.00% on a harder 1,024-prompt external-family diagnostic. A 10,000-problem survey and 256-update follow-up are queued, with no result claimed.

Next gate Audit verifier and semantic-group separation, then require paired gains without harder-set regressions.

04 / Tool callingSmoke passed · full run queued

Calls, arguments and abstention

A tool-use continuation mixes 36,642 tool training examples from oellm-eu-tooluse-v1 with instruction replay at equal rendered-token volume. The five-update LUMI smoke passed after a template fix; validation, full SFT and evaluation remain queued.

Next gate Measure valid syntax, tool choice, exact arguments and unnecessary calls against the parent. The source data are English, so this is not yet a multilingual tool-use claim.

The shared research standard

A checkpoint is a result only after its comparison

Across SFT, DPO, RLVR and tool use, the workflow pins the parent and data, runs a small executable gate, saves interpretable checkpoints, and measures both target gains and regressions. Failed launches and negative results belong in the record.

Why these gates matter

The public 9B SFT model card shows how easy it is to overread a headline: one math source was 18.77% of rows but 64.41% of tokenized data; 4K SFT sequences coexist with a 256K configured context; and a 40/40 retrieval probe coexisted with 0/5 exact-format compliance at 128K. It reported no held-out SFT-source validation split. Each fact changes what a later experiment needs to measure.

LUMI jobs and run outputs checked 5 October 2026. Public links provide model, dataset and code context; LUMI-only observations remain provisional until their full run artifacts are released. The PDF details the methods and limits.
